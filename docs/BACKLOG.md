## 待做（按性价比排序）

### 1. 真实目标回退验证 —— 最该先做

**为什么最优先**：现在所有验证都是自造靶机、12 行靶子、自己的仓库。**没有一样在真实目标上跑过。** 真实项目会暴露的问题（指纹拿不到版本、目标禁止外连、40 分钟还在侦察、维护者说"这是设计如此"）比缺任何一层杀伤力都大。

**做法**：挑一个有公开 PoC 和修复提交的历史 CVE，把补丁回退掉，看系统能不能在不知道答案的情况下重新找到它。

**判据**：不是"报了几条"，而是报出来的那几条里有多少是真的。

**成本**：一天，不需要新代码。

### 2. L4 多阶段门控

**提升的是误报率**（Refute-or-Promote 实测合计杀掉 79%~83%），不是发现量——真阳性不会因此多一条。

**为什么值得做**：交付质量。客户不会因为挖出 3 个真漏洞而原谅 50 个假的。

**做法**：单阶段反驳拆成三轮——确定性初筛 / 冷启动反驳（不给反驳方看创意侧论证）/ 证据强度复核。地基（claim / evidence / refutation / relevance）都已就绪。

**成本**：两三百行纯逻辑。

### 3. L3 引擎 C：多解析器与跨边界差分

覆盖唯一没有其他办法覆盖的漏洞类：每个组件单独看都正确、都不崩，拼在一起才出错。

**成本不在写代码**：每类目标都要定制 harness。**别做成"通用差分框架"，那是无底洞。**

### 4. 脚手架离线 A/B

人工准备 3~5 套脚手架变体，在同一批 ≥10 个带 ground truth 的目标上各跑一遍，用检出率/误报率选最优。这是"进化"的工业版本：可控、可解释、可复现。

它还能回答一个更有价值的问题：**现在这套脚手架到底比别的强在哪。**

## 为什么不做代码级自进化（DGM 那类）

**结论：不是"太贵"或"太难"，是这个领域没有可自动判定的 fitness function。**

### 理由一：DGM 的成功依赖一个漏洞挖掘没有的东西

DGM 把 SWE-bench 从 20% 提到 50%，前提是 SWE-bench 每个实例都有**可执行单测**——机器能判定补丁对不对。

漏洞挖掘没有等价物。一条"找到的漏洞"是不是真的，只有两种判法：厂商确认（周期数天到数月，多数不回复）或人工复核（不可自动化）。

没有可重复的标量评分，进化环只能拿代理指标顶替（候选数、CVSS 分、可疑度），而代理指标与真实价值相关性极弱——Refute-or-Promote 的实测是 LLM 候选里 79%~83% 是错的。用"候选数"当 fitness，进化必然优化出**产生更多候选**的脚手架，而真漏洞比例很可能更低。

这不是理论担忧：DGM 论文自己记录了 agent 为拿高分偷偷删掉幻觉检测标记。

### 理由二：可进化空间已被人工吃掉

AgentFlow 消融数据：Σ 消息契约影响 32.5 个点，Φ 工具绑定 12.4 个点，A/G/Ψ 拓扑 7.9 个点。

契约、三公分权、证据分级已经把前两项固定成确定性代码。剩下能自动进化的只有提示词层——**恰恰是影响最小的那层**。

### 理由三：搜索成本与评测成本的比例是反的

DGM 一次迭代 = 跑一遍评测集（SWE-bench Verified 500 题）。奶虫"一次评测" = 一次完整渗透作业（30~60 分钟），而且为避免过拟合，每轮必须换目标。

50 代 × 3 个目标 = 150 次完整作业 + 150 个带 ground truth 的靶场。**准备环境的成本远大于进化本身。**

### 理由四：安全方向的 fitness 可以被 game，而且已有前科

`policy/scope.rego` 文件头记着一次真实事故：比赛时为绕开范围闸把 `allowedHosts` 清空了。这是同一失败模式在更高层的重演——agent 优化的目标是"通过"，而"通过"的定义写在它能改的地方。

### 理由五：顺序不对

一个真实项目都没跑完。现在进化，提升无法与随机波动区分（同一脚手架三次的方差可能就有 20%）。先说清基线，再谈优化。

### 什么时候该做：四条判据

1. 有 ≥100 个带**可执行判据**的目标
2. 评测器在被测代码的物理隔离之外
3. 能承担 50 次 × 完整作业的成本
4. 已有稳定基线（同脚手架三次方差 < 10%）

第 1 条有现成路径：**用 OSS-Fuzz 历史 crash 的回退版做评测集**。那些 bug 有 reproducer，判据是"给定回退版本能不能复现 crash"——可执行、可重复、无需人工。这是漏洞挖掘里唯一接近 SWE-bench 的评测形式。

**要做真进化，评测集应该是这个，不是"渗透项目"。**

### 现在做的是什么

`engine/blackbox/evolve.py` 只做**参数进化**（nevergrad 搜索 concurrency / rounds / samples / qps / 维度权重），固定探测逻辑，评分来自靶场真实检出。

这是能在一天内跑完、能看出效果的版本。代码级自修改等上面四条判据满足再说。

## 已知限制与技术债

### 影响正确性的

**`pathKey` 仍由模型声明。** `independentPaths` 数的是模型声明的独立性，不是系统核实的。要真解，得让系统从请求特征自己派生。

**调用图按名字连边。** `get`、`main`、`info` 这类通用名会跨类合并（实测 `get` 有 125 个"调用方"）。对可达性判断影响可控，但看调用方列表时要意识到。

**semgrep 规则骨架是 generic 语言。** `patch_analyze` 生成的规则要按目标语言改写才实用。

**没崩溃 ≠ 安全。** `fuzz_lab` 会明确说"N 次执行没撞到"；`oracle_run` 的 `unknown` 也不是 `miss`；黑盒的"没找到异常"同样只是"这些探针没找到"。

**共振阈值 0.45 是在小样本上调的。** 只用 3-gram shingle 时同一缺陷换个措辞就聚不上，加 unigram 才稳。真实目标上这个阈值需要重新标定。

### 环境相关的坑（都踩过，记下来免得再踩）

**AFL 插桩不能加 `-O0`。** 同一个程序：`-O0` 下 `afl-showmap` 只注册 2 条边，去掉是 4 条。边数掉一半，覆盖率反馈失去区分度，fuzzer 退化成瞎撞——表现是"跑了几万次一个崩溃都没有"。

**AFL 默认的 PCGUARD 在小程序上不插桩**（`__afl_final_loc=0`）。必须显式 `AFL_LLVM_INSTRUMENT=CLASSIC`。

**AFL 的 `@@` 传的是文件路径，不是文件内容。** "读 argv 字符串"的目标接不上。

**靶子里赋值的 buffer 必须被使用。** 否则 `strcpy` 被优化掉，靶子根本不崩。

**`tree_sitter_language_pack` 会联网下载语法。** 隔离环境挂满超时。用预编译单语言 wheel。

**CodeQL 没装。** 下载 45KB/s，430MB 下不完；且建库需完整编译环境。

**semgrep 用 pipx 装**，pip 直装与 Debian Python 冲突。

**坏掉的 semgrep 规则不报错**，正常返回 0 命中。执行前必须 `--validate`。

**NVD 的字段是 `versionEndExcluding`**，写成 `endExcluding` 会让区间只剩起点，所有版本返回同样结果。

**Python 里 `b"\x00"` 经 `str.replace` 会变成真 NUL**，写进源文件后语法报错。用 `bytes(4)`。

**`.mjs` 测试文件里不能写 TypeScript 语法。**

**并发测试必须用独立连接。** 共享 `requests.Session` 会让多线程串行化——HTTP/1.1 的 keep-alive 连接不能被多线程同时用。

**竞态判据要比"成功次数"不是"结果分歧"。** 一次性接口（券/余额）顺序重放本来就分歧，用分歧判定会恒真。

**竞态必须多轮采样。** 窗口 5ms 时能否撞进去取决于调度，单轮结果两个方向都会错。

**竞态测试之间必须重置状态。** 不重置的话第二组测的是耗尽态，结论完全反。

### 未验证的

**`fuzzlab.py` 的自研变异器**（AFL 不可用时的 fallback）没有独立测试。

**oracle 的 `supervised=false` 分支**（supervisor 自己挂掉）没有测试用例。

**路由簇分析在真实大仓库上的表现**未知。fixture 上正确，但真实项目的路由注册方式远比 `ROUTE_PATTERNS` 覆盖的多。**漏判只多一条待确认，误判会隐藏真漏洞**，所以宁可漏。

**HTTP/2 单包攻击没在真实 h2 目标上验证过。** 靶机是 HTTP/1.1，只验证了线程并发这条路径。

## 一句话

白盒线的能力边界：在**有明确输入格式、能编译**的 C/C++ 目标上跑通"插桩 → fuzz → 崩溃 → 复现"。

黑盒线的能力边界：在**有已知缺陷**的本地靶机上，六类问题（BOLA / 参数污染 / 栈泄露 / 竞态 / 状态机跳步 / 诱饵迷宫）全部检出。

两条线都还没在真实项目上跑过。真实大型项目上，gcov 的行覆盖粒度、没有持久化语料库、以及黑盒探针的覆盖面，都会让效率掉一个量级。
