# 实战暴露的问题（TPCTF 2025 superbooru，2026-11-11）

> 环境：`/root/proj` 项目 runtime，headless profile，deepseek-flash，禁网（`web_search`/`web_fetch` 由 secops denylist 硬拒）。
> 靶场：`/root/异构agent/ctf/superbooru/files`（rev 题，给源码 + SQLite + 规则数据）。
> 观察窗口：单轮 45 分钟，65 次工具调用。

## 1. 编排层零使用（最严重）

65 次工具调用里，`bash` 65 次，`council_*` / `agent_dispatch` / `agent_directions` / `claim_*` **一次都没有**。

不是工具坏了——同一套工具在真机上跑 `council_run`、`agent_dispatch` 都验证过。
问题是**它不知道什么时候该切过去**：

- 工具描述写的是「多方向扫描时用」，而这个任务是单点深挖，模型判断「不需要」，这个判断本身没错。
- 但没有第二层信号告诉它：即使不做多方向，`claim_assert` / `claim_evidence` 也能用来记「我验证了什么」。
- 结果：一个月的证据链、三公、误报账本，在最需要「证明我确实解出来了」的场景里完全缺席。

**结论**：编排层只覆盖了「扫描型任务」，没有覆盖「推理型任务」。后者恰恰更需要证据留痕。

## 2. 工作目录污染 runtime

`/root/proj/work` 被建在项目 runtime 的 cwd 下，28 个脚本、90MB pickle。
根因在 `index.ts`：`createQueueAttempt({ cwd: process.cwd() })`，模型顺着 cwd 就往下建目录。

应该有一个独立的 agent 工作根（比如 `<baseDir>/work/<session>`），并在 system prompt 里点明。

## 3. 没有自我纠偏

从第 40 次调用开始，它就进入「换个爆破顺序再试一次」的循环：
`truth.py` → `truth2.py` → `support.py` → `support2.py` → `anf.py` → `bruteorder.py`。

每一轮都是同一个假设的变体，没有一次回头问「我这个假设本身对不对」。
系统里没有任何机制在检测这种「重复投入无进展」——`DecisionPolicy` 有 `STALL_WINDOW`，
但那是 pre-step 层面对「连续拒绝」的检测，管不到「连续同方向尝试无产出」。

## 4. 没有中间汇报

45 分钟，零个阶段性结论。用户只能看 session 原始日志才知道它在干什么。
headless 模式默认一次性交付，长任务下这是不可用的。

## 5. 拿数据就开算，不先建题目意图模型

它第一步就把 `implications.txt` 当数据集解析（30k tag、50k 规则），
然后在这个数据集上做真值表 / 支持集 / ANF 分解。

而题目的源码 `superbooru/*.py` 才是入口——`check_flag` 怎么被解析、
提交的 flag 走哪条路径，决定了那份数据到底被怎么消费。
它读了源码（第 30 次调用一次性 cat 了全部 .py），但读完之后仍然回到数据上。

**这是一个可复现的行为模式**：手上有一个「看起来像密码学/编码的东西」时，
模型倾向于直接对它下算法，而不是先确认它的语义角色。

## 6. 生成物无管理

28 个脚本、90MB pickle，没有清理、没有归并、没有「哪些是结论哪些是草稿」的区分。
长任务下这会拖垮上下文与磁盘。

## 7. headless 缺少「卡住了怎么办」

它没有求助通道。纯 headless 下没有人可问，但它也没有输出一个结构化的
「我卡在 X，需要 Y」——那是唯一能让人类 30 秒内推它一把的东西。

---

## 待解决清单（按优先级）

1. 工作根隔离（`cwd` 不能是 runtime 自身）—— 改动小、影响直接
2. 编排层适用面：给 `claim_*` 一类工具补「推理型任务」的使用场景说明
3. 停滞检测：连续 N 次同类尝试无产出时主动要求换假设
4. 长任务阶段性产出：headless 也应有中间结论落盘
5. 「卡住」的结构化上报通道

---

## 已解决：时间信用（时间从配额变成投资回报）

用户提出的机制，2026-11-11 实现并验证：

- **基础 30 分钟**，每次实质进展 **+10 分钟**，上限 2 小时。
- **进展由系统判定，不由模型自述**：带 falsifier 的新断言、通过锚点校验的强证据、
  独立路径增加、成功证伪——四个来源全部来自 `ClaimStore` 的事件，模型说「我有线索」不算。
- **同一件事只计价一次**：`(kind, claimId)` 去重；两次续期之间有 2 分钟冷却，
  但冷却期内被拒的进展**不作废**，只是这次不计价。
- **到点先提醒再拒绝**：剩 5 分钟时注入收尾提示，耗尽时拒绝进入下一个 step，
  要求输出结案报告（确认了什么、排除了什么、还差哪一步）。
- 新增 `time_budget` 工具：模型能看到余额和每笔续期的来源。
  看不见余额的人不会省着花。

真机验证：`claim_assert` 带 falsifier 后，`remaining` 从 30m 变 39m57s，
账本记 `+10m hypothesis on claim-xxx`。

这个机制补充了 §1 的缺口：编排层在推理型任务里缺席，是因为 `claim_*` 只被
描述成「安全断言」。时间信用给了它一个新角色——**挣时间**。现在不用它就没有时间，
这是行为层而不是提示层的驱动。
